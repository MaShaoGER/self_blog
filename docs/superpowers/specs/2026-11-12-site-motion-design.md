# 全站动效与交互反馈

日期：2026-11-12

## 意图

博客保持现有的简洁工业平面版式，但访客在任何页面都应能直观感到"这个站是活的"：进入页面有次序，操作有回应，换页有衔接。此前只有点开文章时标题滑动一处，感知太弱。

## 目标

- 每个前台页面进入时都有同一套入场语言：内容自上而下依次亮起，结构线从左画出。
- 站内任意换页都有一次短促过渡，顶栏与页脚不动。
- 所有可操作的东西（按键、链接、目录行、标签、输入框、旋钮、拨杆）都有明确的悬停、按下、到位反馈。
- 首页状态面板是真控件：旋钮按分类筛目录，荧光屏随操作读数。
- 文章页：标题从目录行滑到页头，图片从原位展开，目录标记随阅读滑动，评论提交有印章反馈。

## 非目标

- 不改版式、配色、字体和信息结构。
- 不做独立的装饰主视觉、插画、粒子、3D 场景。
- 不改后台界面。

## 反目标

- 动效拖慢内容出现，或在减弱动效、无 JS 时让内容不可见。
- 无限循环的装饰动画（在线指示灯的呼吸是唯一例外）。
- 为了拟真另造不承载信息的零件。

## 约束

- 动效只挂在已有元素上；只动 transform / opacity / clip-path / 颜色，位移不超过 12px。
- 统一时长与缓动，定义在 `app/motion/tokens.css`。
- 入场的起始状态写在 `@keyframes` 的 `from` 里，默认样式即终态。
- 尊重 `prefers-reduced-motion`；不新增依赖。

## 方案比较

1. **只做细节微动**（按键、行悬停）：改动最小，但已被证明感知不足。
2. **全站统一动效层（采用）**：一份约定加四个按区域划分的样式文件，换页、入场、控件、阅读四处同时生效。感知强，且不新增任何界面元素。
3. **新增动态主视觉**：感知最强，但此前的中央机械臂方案已被否定为复杂、看不出用途。

## 结构

- `app/motion/tokens.css`：时长、错开间隔、缓动与约定。
- `app/motion/chrome.css`：换页过渡、导航指示线、顶栏滚动状态、主题切换。
- `app/motion/lists.css`：各列表页的页头入场、逐行入场、行悬停。
- `app/motion/reading.css`：灯箱展开、目录标记、阅读进度、复制按钮、评论、参数表。
- `app/motion/controls.css`：键帽按钮、链接、编号标记、荧光屏刷新、输入框、状态页。
- `components/site/home-deck.tsx`：首页旋钮、荧光屏与目录的共享状态。
- `components/site/post-link.tsx`：目录行整页预取与文章标题滑入。

## 已定的实现取舍

- 文章标题滑入不用 React 的共享视图过渡：目录滚动后两端无法配对（实测归档页不滚动成功，滚动 300px 与首页均失败），改为点击时记录位置、文章页自行滑入。
- 目录行在悬停或聚焦时才整页预取，避免点进文章先闪加载占位。

## 留给实现者

- 浏览器后退时标题的反向动画。
- 触屏设备上整页预取的触发时机。
